# OpenCL implementation provenance

`vendor/ed25519.cl` and `vendor/LICENSE` were obtained from [WincerChan/SolVanityCL](https://github.com/WincerChan/SolVanityCL), commit `697719aadcaee76aac485f7a506299202d16d1f4`. The upstream component is licensed under GPL-3.0; its license is preserved alongside the source. The derived GPU program, consisting of `engine.py`, `filter.cl`, `search.cl`, and the vendor kernel, is provided under the same GPL-3.0 terms. The web frontend communicates with this separate local program through JSON messages.

The application does not invoke the upstream incremental-seed search kernel. It retains the Ed25519 and Base58 primitives, supplies independent 32-byte seeds from the operating system's cryptographic random generator for every candidate, and uses a replacement search entry point with atomic result allocation. The local worker checks 128 random GPU public keys against PyNaCl on startup and verifies every emitted match independently on the CPU. This validation is not an independent cryptographic audit.

Bitcoin phrase acceleration uses project-authored OpenCL SHA-512/HMAC/PBKDF2 code implementing FIPS 180-4 and BIP39. The standard SHA-512 constants were cross-checked against `@noble/hashes`; its MIT license is copied to `vendor/noble-hashes-LICENSE.txt`. Bitcoin CPU derivation uses `mnemonic==0.21` for the BIP39 English word list and entropy encoding, and `coincurve==21.0.0` for native libsecp256k1 public-key operations. Python `hashlib`/`hmac` supply independent seed verification and BIP32 hashing. Installed package distributions retain their license files. Bitcoin GPU matching shares the project's `filter.cl` rules with Solana; it does not use SolVanityCL's Ed25519 key generation.

Bitcoin Fast uses project-authored OpenCL secp256k1 field and fixed-base point operations, SHA-256, RIPEMD-160, and Bech32 encoding. Its public multiplication table is generated locally using the existing coincurve dependency. It uses independent OS-random keys, not incremental private-key search. Native coincurve and the existing noble/scure libraries independently verify retained results. No additional third-party kernel or dependency is bundled.

Ethereum Fast reuses the project-authored secp256k1 and batch inversion routines and adds project-authored OpenCL Keccak-256 with Ethereum legacy padding. A CPU Keccak reference plus native coincurve checks emitted addresses; the JavaScript bridge independently checks them with noble and applies EIP-55 casing. No additional dependency or third-party kernel is bundled.
